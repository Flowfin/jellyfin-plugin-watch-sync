# Every ordered pair of states the two sides can hold, per row of the conflict table,
# with the answer in the data rather than in the code. This is the third condition of
# #81, and the mirror column is the fourth.
#
# Three kinds of line, told apart by the first field.
#
#   setting :: field :: key :: value
#       the context one field's rule is driven in. PlaybackPositionTicks takes now and
#       toleratedSkew, PlayCount takes agreed. A key the driver does not know fails.
#
#   state :: field :: name :: played :: playCount :: positionTicks :: lastPlayedDate
#       one side's state, named. The date is an instant in UTC or "-" for a side that
#       never played the work. Every state carries all four members of SyncedState, so a
#       rule that started reading a member it does not read today is driven with a real
#       value rather than with a default nobody chose.
#
#   pair :: field :: here :: peer :: answer :: value :: here-loses :: peer-loses :: mirror
#       the answer for one ordered pair. The value is what the rule answered with, "-"
#       where it answers with none. The two loses columns are what that side lost, "-"
#       where it lost nothing: a discarded position for the two position-carrying rules
#       and a shortfall for PlayCount, which is the same statement in that row's units.
#
# Blank lines and lines beginning with # are ignored.
#
# WHICH FIELDS ARE HERE IS NOT A CHOICE MADE IN THIS FILE. Conflict/coverage.txt says
# which rows of the table have a rule, and this file is required to hold exactly those
# and no others. The day the LastPlayedDate row gained a rule that register moved it to
# covered and this file was missing a field until its pairs were walked, which is the
# same fail-closed shape coverage.txt uses for the row itself and is what the last
# section of this file is.
#
# THE VALUE COLUMN IS IN THE ROW'S OWN UNITS. Three rows answer with a number of ticks
# or a count and one answers with a moment, so the column takes an instant as well, in
# the same written form the state lines use. It is read as the ticks of that instant, so
# a moment and a number of ticks are one column rather than two, and a value written in
# the wrong form for its row fails to parse rather than comparing as something else.
#
# THE PAIRS ARE THE WHOLE CROSS PRODUCT AND THAT IS CHECKED. Every ordered pair of the
# states declared for a field appears exactly once, both orders of a pair included and
# a state held against itself included. A hand-written cross product goes wrong by
# leaving out one direction of one pair, which is what the near-miss fixture beside
# this file is.
#
# THE MIRROR COLUMN IS EXECUTED RATHER THAN TRUSTED, in both directions, which is why
# it carries no reason per entry. "mirrored" means running the rule with the two sides
# exchanged answers the same thing with the two loses columns exchanged, and it is
# asserted. "asymmetric" means it does not, and that is asserted as well, so a stale
# declaration in either direction reddens instead of reading as a decision somebody
# took.
#
# There is one asymmetric branch in the tree today and it is deliberate.
# PositionRecency reads the peer's last played date against this server's present
# moment and never reads its own against it, because a peer claiming a play in the
# future is the failure that rule names and this server's own clock is the thing every
# other reading here is already relative to. So a state whose date is ahead of the
# present moment refuses the exchange when the peer holds it and is an ordinary reading
# when this server holds it.
#
# WHAT A VALUE THE SERVER CANNOT PRODUCE DOES IS NOT IN THIS TABLE, and it is asserted
# rather than left undefined: a position below zero and a count below zero are refused
# by the rules, and ConflictOrderedPairTests holds each refused state against every
# state declared here, in both positions, rather than adding a row to the cross product
# for a state no answer exists for.

setting :: PlaybackPositionTicks :: now :: 2026-01-01T12:00:00Z
setting :: PlaybackPositionTicks :: toleratedSkew :: 00:01:00
setting :: PlayCount :: agreed :: 2
