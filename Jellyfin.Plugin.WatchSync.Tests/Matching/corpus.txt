# The matcher corpus, one situation per row.
#
# Fields are separated by " :: ": the identifier, the situation the row represents,
# what this server's library holds, what arrives from the peer, and the answer.
#
# A row is data rather than a case in code so that a situation can be added without
# writing a test. Every row in this file becomes one executed case, and a row the
# parser cannot read fails rather than being skipped.
#
# An item is written as its kind, a space, and its fields separated by ";". The kinds
# are the ones docs/matching.md gives a key rule to. A field name is a provider the
# item was scraped by, "series." and a provider for the series it belongs to, "order"
# for the ordering the series is numbered under, or "season", "episode" and "last" for
# the position. A kind on its own is an item carrying nothing.
#
# The library field holds zero or more items separated by " | ", or "-" for a library
# that holds nothing. A library item that produces no key is not in the index at all,
# which is what an unkeyed local twin in a row is there to show. The one item a match
# is expected to resolve to carries a leading "*", and it is present exactly on the
# rows whose answer is "matched".
#
# "\s" in a value is one space. It is written that way because the field separator is
# surrounded by spaces and a reader trims each field, so a value whose whole point is
# its surrounding whitespace could not survive being written literally.
#
# The answers are "matched", "ambiguous", "no-match", or the name of the refusal the
# peer's item produced instead of a key. The refusal names are members of
# MatchKeyRefusal and are read from that type rather than listed here, so a member
# added with no row producing it fails.
#
# THERE IS NO COLUMN FOR A TITLE, A YEAR OR A RUNTIME, and that absence is the point
# rather than an omission. Nothing in the matcher reads any of them, so there is
# nothing for such a column to be given to. docs/matching.md is where that refusal is
# argued and StorageIdentityGuardTests is what refuses a source that reaches for the
# neighbouring class of value.
#
# IdentifierRefusal is not an answer here. It says why one stored value was not usable
# and several of its members reach the same MatchKeyRefusal, so it is a reading inside
# the derivation rather than something a record of an unmatched item holds.
# ProviderIdentifierTests covers it value by value.
