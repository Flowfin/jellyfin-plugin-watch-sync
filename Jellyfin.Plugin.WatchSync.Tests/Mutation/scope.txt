# What the mutation run covers, one component per row.
#
# Fields are separated by " :: ": the directory inside the plugin project, its
# state, and the reason. "." is the project root, meaning the sources that sit in
# no directory at all.
#
# The states are:
#
#   mutated  the run mutates it and the directory is in the tree
#   awaited  the run is already scoped to it and the directory does not exist yet
#   excused  the run does not mutate it, and the reason column says why
#
# MutationScopeTests holds this file and stryker-config.json to each other in both
# directions, and it holds each row's state to the tree: a component added to the
# plugin project and named in neither file fails, a glob in the configuration with
# no row here fails, and a row saying "awaited" whose directory has since appeared
# fails until somebody moves it to "mutated". That last one is the whole reason
# the middle column exists. #103 scopes the run to the matcher and the conflict
# resolver, one of which is not written, and a scope that named it and then missed
# it because it landed under another name would be a run reporting a score for
# half of what it claims to cover.

. :: excused :: The plugin's identity, the pages it serves and the version the server reads. It composes nothing and decides nothing, so a mutant here is a changed constant rather than a wrong answer.
Configuration :: excused :: The configuration type and the page it serves. The type carries no setting yet and says so in its own body; which settings exist and where each is stored is #58, and a run over an empty type measures nothing.
Document :: mutated :: The version every document in the store carries, and the reading that refuses one written by a version this code does not know. A survivor here is an older reader accepting a newer document, which is the quiet loss #69 exists against: it reads what it understands, writes the document back without the rest, and nothing says anything happened.
Matching :: mutated :: The matcher. A survivor here is watch history landing on the wrong item or on none, which is the failure this plugin exists to refuse.
Model :: mutated :: The set of fields that move, and the unit one transfer is about. The field set is a declaration the suite compares against the server's own record, and it was the whole of this directory while the excuse here said a mutant would be a changed constant rather than a wrong answer. #13 put a decision beside it: which kinds may be a transfer subject at all. A survivor there is a series accepted as one, and applying a series means marking every episode the peer holds under it, which is the mass marking this plugin exists to refuse.
Peer :: mutated :: What arrived from another machine, bounded and stripped before a page or a log line is built out of it. A survivor here is a peer-chosen string reaching a dashboard an administrator is signed in to, or forging a line in a log, which are the two failures #63 is about and neither of them looks wrong from outside.
Storage :: mutated :: Where the store sits, what creating it does, and how a document gets into it. The excuse here said the directory held no rule that could be subtly wrong and that the documents it would hold were not written. #70 wrote the write path and both halves stopped being true. A survivor here is a write that stopped being atomic while every fact about it stays green: the bytes reaching the document's own name rather than the file beside it, the comparison that decides whether another caller replaced the document in between, and the boundary of the room a write has left. Each of those loses somebody's agreed record and none of them looks wrong from outside.
Conflict :: mutated :: The conflict resolver. A survivor here is a rule that stopped deciding and a resolution that looks the same from outside, which is why #103 names it beside the matcher. #33 landed the first row, the play count reckoned against what two sides last agreed, so the directory is in the tree; #30 writes the table and the rest of #31 to #38 write the other rows.
Transfer :: mutated :: The list a peer reads a change from, and the collapse that keeps it the size of the work outstanding rather than the size of the evening. A survivor here is a fold that stopped folding, which looks like an ordinary list from outside and reaches a peer as an evening of contradictory changes, or an answered position that stopped being removed, which offers a peer a point somebody passed on the way to finishing the work. The pair the collapse hands to the ratchet is the one to watch: a mutant that inverts either half of that answer leaves both files reading correctly and the rule deciding the opposite way.
Versions :: mutated :: Where a position from a peer lands when one work is held in several versions, which is #28. A survivor here is a tick from a ninety minute cut written onto a two hour one, and it looks like a resume point rather than like a defect: the person is dropped into a scene they had not reached, and nothing on either server says a position was moved rather than dropped.
